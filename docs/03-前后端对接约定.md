# 前后端对接约定

> COMP 3500SEF / 8500SEF — 选举管理与投票系统
> **发给成员 1、2（前端）与 3、4、5（后端）**
>
> 作用：把"怎么对接"约定下来，避免联调时反复扯皮。
> 接口细节看 [API 契约](templates/API-contract-template.md)，
> 唯一权威是后端启动后的 **http://127.0.0.1:8770/docs**。

---

## 一、先记住三件事

1. **后端地址**：`http://127.0.0.1:8770`，所有接口前缀 `/api/v1`
2. **前端地址**：`http://localhost:5173`，Vite 已把 `/api` 代理到后端，**前端代码里不写域名**
3. **字段名一律 snake_case**（`student_id`、`status_label`、`my_vote_status`），前后端都别转换

| 角色 | 成员 | 负责的接口 |

| 前端：选民端 | 1 | `auth/*`、`elections`（读）、`votes`、`receipts` |

## 三、接口契约（必须遵守）

### 3.1 成功：直接返回数据

```json
{ "id": 1, "status": "open", "status_label": "投票进行中" }
```

**不要**期待 `{success: true, data: {...}}` 这种信封 —— 代码没有套。

### 3.2 失败：`detail` 永远是字符串

```json
{ "detail": "您已完成投票，不能重复投票" }
```

前端直接展示 `detail` 即可。**不要再自己拼错误文案**（后端已经写成中文了）。

> 历史坑：422 原本返回数组，已在 `main.py` 统一压平。如果看到 `[object Object]`，说明用了旧代码。

### 3.3 枚举值：前后端必须一致

| 字段 | 取值 |
|---|---|
| `status` | `scheduled` / `open` / `closed` / `published` |
| `my_vote_status` | `NOT_VOTED` / `VOTED` / `NOT_ELIGIBLE` |
| `tally_method` | `fptp` / `irv` |
| `role` | `VOTER` / `ADMIN` / `AUDITOR` |

**前端不要自己定义另一套中文枚举做判断**，展示时用后端给的 `status_label`。

## 四、认证怎么走

```
① 登录  POST /api/v1/auth/login  {student_id, password}
        ← {access_token, token_type, user}

② 本地保存 token（localStorage）
③ 之后每个请求加头：Authorization: Bearer <token>
④ 刷新页面：调 GET /api/v1/auth/me 验证；401 就清 token 跳登录
```

**已实现**：`frontend/src/api.ts` 的请求拦截器会自动加头，前端不用每次手写。

**注意**：`EventSource`（SSE）**不能带请求头**，所以两个 `/events/*` 端点不需要登录。
也正因如此，推送内容只能是聚合数据，不能带个人信息。

## 五、SSE 怎么接

### 后端推送什么

```
event: open       data: {"channel":"turnout","election_id":1}
event: turnout    data: {"election_id":1,"voted":21,"total":30,"percent":70.0}
event: heartbeat  data: {"ts":12345.6}
```

### 前端怎么订阅

```ts
const es = new EventSource(`/api/v1/events/turnout?election_id=${id}`)
es.addEventListener('turnout', (e) => {
  const data = JSON.parse(e.data)   // {election_id, voted, total, percent}
})
```

**三条约束**：

1. **投票进行中只推投票率**，不推各候选人票数（公平性要求，SRS 领域需求 DR-1）
2. 票数只在**选举截止后**通过 `/events/results` 推
3. `EventSource` 自带重连，UI 显示"重连中"即可，**不要弹错误框**

## 六、状态机与按钮可见性

选举状态只能沿这条线走，**前端按钮必须按状态禁用**：

```
scheduled ──▶ open ──▶ closed ──▶ published
```

| 当前状态 | 允许的操作 | 前端按钮 |
|---|---|---|
| `scheduled` | 开放投票 | 显示「开放投票」 |
| `open` | 截止 | 显示「截止」；允许投票 |
| `closed` | 计票公示 | 显示「计票公示」 |
| `published` | 无（终态） | 不显示任何操作按钮 |

**后端也会拒绝非法迁移**（返回 400），前端禁用只是体验优化，不是安全边界。

## 七、错误处理对照表

| HTTP | 场景 | 前端应该怎么显示 |
|---|---|---|
| 401 | 未登录 / token 过期 | 清 token，跳登录页 |
| 403 | 无权限 / 不在名册 | 提示"你没有权限"或"你不在选民名册内" |
| 404 | 资源不存在 | 提示"找不到该内容" |
| 409 | 重复投票 / 选举未开放 | **直接展示 `detail`**（后端已写得很好懂） |
| 422 | 表单参数不合法 | 直接展示 `detail`，可高亮对应输入框 |
| 500 | 服务端异常 | 提示"服务暂时不可用，请稍后重试" |

## 八、空值与边界

| 字段 | 可能为 null | 前端处理 |
|---|---|---|
| `opens_at` / `closes_at` | ✅ | 显示"未设置" |
| `winner_name` | ✅（并列） | 显示"无单一最高票" |
| `rounds` | 数组可能为空（FPTP） | 只对 IRV 展示逐轮表 |
| `results` | 未截止时为空数组 | 显示"尚未公布" |

## 十一、可选的改进（谁有空谁做）

**让 TypeScript 类型自动生成**，避免手写 `api.ts` 里的 interface：

```bash
npx openapi-typescript http://127.0.0.1:8770/openapi.json -o frontend/src/api-types.ts
```

## 十二、遇到问题怎么办

| 现象 | 大概率原因 | 解决 |
|---|---|---|
| 前端请求 404 | 少了 `/api/v1` 前缀 | 检查 `api.ts` 的 baseURL |
| 401 一直出现 | token 没带上或已过期 | 重新登录；检查拦截器 |
| 页面显示 `[object Object]` | 用了旧的错误解析 | 更新 `api.ts`（已修） |
| SSE 一直不更新 | `election_id` 传错 / 选举已截止 | 检查 URL 参数与选举状态 |
| 跨域报错 | 没走 Vite 代理 | 前端访问 5173，不要直连 8770 |
| `npm run dev` 报错找不到模块 | 没装依赖 | `cd frontend && npm install` |
